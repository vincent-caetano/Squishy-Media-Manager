## Pick the quality you actually want

Downloads used to take whatever YouTube considered best. On a 4K upload that means a 343 MB file — even when you only wanted something to compress down anyway.

Pasting a link now lists every quality the video publishes, each with the size it will actually produce, and downloading is one click on the row you want. **Audio only** is the last row in the same list.

The sizes are real rather than indicative: each row downloads the exact stream it quoted, so a row saying 45.4 MB does not land a 343 MB file because yt-dlp preferred a different codec. Rows prefer streams that merge into MP4 without re-encoding, and pair with AAC audio for the same reason.

Two details worth knowing about the labels. They follow YouTube's own naming, which tracks the long edge — a 2160p stream on a 2:1 video is 3840×1920, and calling that "1920p" would match nothing you have ever seen for it. And where a quality is offered in several codecs, the row picks the smallest stream at that resolution, so 1080p may be AV1 rather than H.264.

## Downloads are roughly twice as fast

Paste-to-file on a 12-minute video went from 22.0s to 9.1s.

**Nothing is fetched twice.** The preview already resolves the link; the download used to throw that away and resolve it again from scratch. It now reuses the preview's result, which is about two seconds off every download. A retry still re-resolves, so a stale result costs nothing beyond the attempt it was already going to make.

**The default is 1080p rather than "best available".** Every higher rung is still one click away in the list — this only changes what happens when no quality was picked explicitly, which was the single biggest reason a download felt slow.

Downloads also skip the HLS manifest lookup, which Squishy never used, and fetch fragments concurrently.

## Copy the link a file came from

Files downloaded from YouTube remember where they came from. The queue shows a link button on those rows, with **Copy Video Link** in the right-click menu, and the single-file view carries the URL in its details. Files added from disk have no link and show neither.

## Fixes

- Pasting a link could silently do nothing. The field lived in a layout that swapped as soon as text arrived, and SwiftUI never delivers `onChange` to a view it replaces in the same update, so the lookup never ran. The field now keeps its place in the view tree as the drop zone comes and goes, which also stops it losing keyboard focus mid-paste.
- **Download Audio** downloaded video.
