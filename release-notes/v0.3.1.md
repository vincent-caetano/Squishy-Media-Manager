## YouTube downloads work again

Two separate problems made YouTube downloads impossible in v0.3.0.

**The download buttons could vanish.** They lived inside the video preview, which only appears once `yt-dlp` successfully returns the title, duration and thumbnail. Every failure path in that metadata fetch returned silently — so a perfectly valid link plus a failed preview left you with a text field, no buttons, and no explanation. The buttons now depend only on the link being a valid YouTube URL, which is all a download ever actually required. The thumbnail and title are decoration.

**Downloads failed with HTTP 403.** yt-dlp's current default player client (`android_vr`) resolves media URLs that YouTube then refuses, and there is no newer yt-dlp to upgrade to. Squishy now retries automatically against `web_embedded,tv_simply,mweb`, which reach the same top-quality formats. The first attempt still uses yt-dlp's own defaults, so this fixes itself upstream without Squishy getting in the way.

## Update in place

The update alert previously only opened the release page in a browser — you still had to download the `.dmg` and drag Squishy into Applications yourself. It now offers **Update Now**, which downloads the release build, checks it against the published `SHA256SUMS.txt`, swaps the bundle and reopens Squishy on the new version.

A mismatched checksum installs nothing. If any step fails, the old copy is put back and relaunched rather than leaving you with a missing app. **Download Page** is still there, and is used automatically when Squishy can't write to its own folder — running from a mounted disk image, for instance — or when a release doesn't publish the assets the installer needs.

## Failures explain themselves

- A failed metadata fetch shows the actual `yt-dlp` error instead of rendering nothing, and says you can still try the download.
- Missing `yt-dlp` says so rather than silently doing nothing.
- Dimmed download buttons carry a tooltip explaining why — missing tool, download already running, or no valid link.
- The retry is visible in the console: what the first attempt failed with, and which player clients the second one is trying.

## Fixes

- Cancelling a download no longer reports itself as a failure.
- A superseded metadata fetch could clear the loading state of the fetch that replaced it, leaving the panel blank mid-lookup.
- `yt-dlp`'s stderr was piped somewhere nothing ever read, so a verbose enough failure could hang the lookup indefinitely.
- Pasting a link while files are already queued now shows the download buttons; previously that panel offered no way to act on the link.

---

**Installing:** download the `.dmg`, drag Squishy into Applications, replacing any older copy. Squishy still needs Homebrew, FFmpeg and yt-dlp; the first-run screen installs them for you.
